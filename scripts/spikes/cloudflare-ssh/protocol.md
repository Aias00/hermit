# Cloudflare SSH carrier: pinned P0 protocol record

Recorded 2026-10-27. This is an experimental compatibility implementation, not a public Cloudflare mobile SDK contract. Protocol inspection initially used local fixtures only; subsequent live verification provisioned an isolated test tunnel, DNS records and owner-only Access applications. Existing Magpie configuration and unrelated services were not changed. Live outcomes are recorded separately in the app implementation log. Endpoint and Access policy belong to the user; no personal hostname or email is built into the package.

## Verified wire facts

| Topic | Evidence and behavior |
| --- | --- |
| Initial URL | CLI [`parseURL`](https://github.com/cloudflare/cloudflared/blob/de6376c5af4a67cbc65258682e5a01781827643d/cmd/cloudflared/access/validation.go#L48-L74) supplies HTTPS if missing and normalizes HTTP to HTTPS. Carrier [`clientConnect`](https://github.com/cloudflare/cloudflared/blob/de6376c5af4a67cbc65258682e5a01781827643d/carrier/websocket.go#L118-L148) changes `https` to `wss` and preserves the URL. It does not append `/ssh`, `/ws`, or an Access login path. A hostname-only URL requests `/`; an explicit path/query remains that path/query. Whether a tenant's routing accepts a path is still deployment-specific. |
| Upgrade | HTTP GET to the original application URL, ordinary RFC 6455 Upgrade/Connection/Sec-WebSocket-Key/Sec-WebSocket-Version headers generated by Gorilla. A valid HTTP 101 and matching Sec-WebSocket-Accept are required. [`createWebsocketStream`](https://github.com/cloudflare/cloudflared/blob/de6376c5af4a67cbc65258682e5a01781827643d/carrier/websocket.go#L47-L91), [Gorilla dial request](https://github.com/gorilla/websocket/blob/v1.5.3/client.go#L188-L239). |
| Application headers | CLI sets `User-Agent: cloudflared/<version>`. User Access token is in `Cf-Access-Token`, not a bespoke Authorization scheme or a required browser Cookie. [`carrier.go`](https://github.com/cloudflare/cloudflared/blob/de6376c5af4a67cbc65258682e5a01781827643d/cmd/cloudflared/access/carrier.go#L80-L97), [`BuildAccessRequest`](https://github.com/cloudflare/cloudflared/blob/de6376c5af4a67cbc65258682e5a01781827643d/carrier/carrier.go#L136-L162). These are observed client headers, not proof that every one is mandatory at the edge. |
| Optional modes | CLI can set `Cf-Access-Client-Id` and `Cf-Access-Client-Secret`; those are service-token credentials and are not built into Moshpit. `Cf-Access-Jump-Destination` is added only for the separate bastion destination mode. A fixed `ssh://127.0.0.1:22` ingress needs no destination header. The P0 adapter does not implement bastion or shared service tokens. |
| Subprotocol/compression | The ordinary Access carrier does not configure Gorilla `Subprotocols` or `EnableCompression`; the corresponding headers are absent by default. `tunnel-protocol` appears in a carrier test fixture, not the production CLI path. The Swift adapter does not request either feature and rejects an unsolicited extension/subprotocol response. |
| Payload | [`GorillaConn.Write`](https://github.com/cloudflare/cloudflared/blob/de6376c5af4a67cbc65258682e5a01781827643d/websocket/connection.go#L30-L65) sends a BinaryMessage containing the bytes supplied by the source stream. No JSON, base64, length prefix, target selector, or SSH-specific envelope is added. Message boundaries are not SSH packet boundaries. Origin uses [`wsutil.ReadClientBinary` / `WriteServerBinary`](https://github.com/cloudflare/cloudflared/blob/de6376c5af4a67cbc65258682e5a01781827643d/websocket/connection.go#L102-L139). |
| Masking/fragmentation | Normal RFC 6455 client masking and continuation frames apply. Gorilla `ReadMessage`/`NextReader` consumes a complete message (with control frames processed during reads); its wrapper retains excess bytes for the next caller read. Native code must preserve a continuous byte sequence across fragments/messages and skip empty payloads. Server-side binary writes are unmasked. [Gorilla readers](https://github.com/gorilla/websocket/blob/v1.5.3/conn.go#L998-L1097). |
| Ping/pong | Gorilla's default ping handler replies with a pong carrying the same payload; its default pong handler does nothing. The carrier does not install a client heartbeat loop. Origin [`Conn.pinger`](https://github.com/cloudflare/cloudflared/blob/de6376c5af4a67cbc65258682e5a01781827643d/websocket/connection.go#L18-L25) uses 54 seconds by default. This is not an edge idle-timeout guarantee. [Gorilla control handlers](https://github.com/gorilla/websocket/blob/v1.5.3/conn.go#L1120-L1192). |
| Close | Gorilla replies to peer close by default; its `Close()` closes the underlying socket without sending/waiting for a WS close frame. `ServeStream` defers that close after `stream.Pipe` returns. Pipe returns when either copy direction ends, with no bidirectional drain wait in this call. There is no resumable stream or TCP half-close extension here. [`ServeStream`](https://github.com/cloudflare/cloudflared/blob/de6376c5af4a67cbc65258682e5a01781827643d/carrier/websocket.go#L30-L41), [`Pipe`](https://github.com/cloudflare/cloudflared/blob/de6376c5af4a67cbc65258682e5a01781827643d/stream/stream.go#L64-L106), [Gorilla Close](https://github.com/gorilla/websocket/blob/v1.5.3/conn.go#L341-L346). |
| Backpressure | Each direction copies synchronously into the destination writer; [`cfio.Copy`](https://github.com/cloudflare/cloudflared/blob/de6376c5af4a67cbc65258682e5a01781827643d/cfio/copy.go#L8-L26) uses a 16 KiB pooled copy buffer when neither side implements optimized copy. It is not a protocol frame-size limit. Gorilla `ReadMessage` can allocate a full message, so its memory behavior should not be copied literally. Native caps/flow control are our policy. |
| Access errors | Official [`IsAccessResponse`](https://github.com/cloudflare/cloudflared/blob/de6376c5af4a67cbc65258682e5a01781827643d/carrier/carrier.go#L118-L134) recognizes a 302 whose Location path starts with the Access login worker path; it then runs the login/token flow and retries once after deleting a rejected cached token. This is not a rule that every 302 is safe to follow. Native transport reports HTTP status and delegates login to the separate auth layer; it never gives HTML to SSH or automatically follows a credential-bearing redirect. |

The official [client-side SSH guide](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/use-cases/ssh/ssh-cloudflared-authentication/) documents a published SSH ingress and `cloudflared access ssh` as OpenSSH's ProxyCommand. It does not document this carrier as a stable iOS SDK. HTTPS authenticates the relay endpoint; SSH host-key verification must still authenticate the target host.

## Native P0 adapter

`Packages/CloudflareSSH/Sources/CloudflareSSH` provides:

```swift
let dialer = try CloudflareSSHDialer()
let tunnel = try await dialer.connect(
    endpoint: userConfiguredWSSURL,
    accessToken: validatedAccessApplicationJWT,
    on: eventLoopGroup
)
// Install the SSH consumer on tunnel.channel on its event loop.
try await tunnel.activate()
// On any SSH setup failure or explicit disconnect:
await tunnel.close()
```

No credentials go into URL parameters, child-process argv, or diagnostics. The API preserves a supplied non-secret path/query to match the source; callers must not supply credentials in the endpoint URL. The package rejects HTTP/WS, URL userinfo/fragments, and invalid header values. TLS uses full hostname/certificate validation with platform trust roots and HTTP/1.1 ALPN; explicit test roots do not turn verification off.

Connection deadline is 15 seconds across TCP selection, TLS, and HTTP upgrade. Cancellation closes all Happy Eyeballs candidates and the selected channel. Incoming upgrade leftovers are explicitly forwarded (`HTTPResponseDecoder(leftOverBytesStrategy: .forwardBytes)`), then cached until `activate()`; the typed NIO pipeline's default leftover policy would otherwise discard a coalesced SSH banner.

The adapter streams binary fragments without collecting entire messages. Each inbound frame and pre-consumer buffer is bounded at 1 MiB. Outbound writes are split into masked 16 KiB binary messages; pending writes have a 1 MiB hard cap, with NIO's socket high/low watermarks set to 1 MiB/256 KiB. Producers should obey channel writability. If they overrun the cap, the adapter fails and closes rather than dropping or replaying bytes. A single oversized write is rejected before sending any of its payload.

P0 schedules a ping every 20 seconds, expecting its matching pong within 10 seconds after the ping write completes; these are client policy, not cloudflared protocol constants. While a ping is queued, a separate 10-second no-write-progress deadline is reset by completed frame writes. A stalled queue fails with `heartbeatWriteTimedOut`; a written ping without its matching pong fails with `heartbeatTimedOut`. Write progress cannot extend the latter deadline, and an early pong prevents a late deadline from being armed. Peer ping is answered even while waiting for the SSH consumer, with control-write failures preserved. Close is sent once with a two-second flush deadline; half-close requests end the whole transport. No reconnect or input replay occurs inside the dialer.

## Local checks and outstanding G1 evidence

The package includes offline frame/upgrade tests and loopback real-TLS tests. They cover binary round trips, fragmentation, interleaved controls, empty frames, masking, coalesced 101+banner with delayed consumer, header injection, non-101 status separation, TLS hostname verification, bounded pending data, heartbeat timeout, cancellation, and handshake deadline. These are local fixtures; the SSH-looking banner is synthetic and is not a real SSH handshake.

The latest macOS `swift test --package-path Packages/CloudflareSSH` run on 2026-10-27 passed all **39 transport tests** and the separate Access target's **10 tests**, with zero failures. This includes 8 heartbeat regressions and 8 diagnostic regressions in addition to the original 23 transport checks. Earlier runs exposed a close-completion deadlock in EmbeddedChannel and HTTP response parts escaping a rejected upgrade; those fixes remain covered, as does classification of transient TLS handshake EOF versus certificate rejection. iOS compilation and simulator validation are recorded in the [app implementation log](../../../docs/design/cloudflare-access-implementation.md).

G1 is **not passed** by these tests. Still required on a user-supplied, Access-protected SSH ingress:

1. Compare official installed cloudflared 2026.10.3 with the Swift dialer against the same endpoint and Access application; verify the exact deployed path/header behavior.
2. Complete real SSH key exchange and authenticate the expected pinned host key through both clients. Reject an unknown/changed key according to the app's existing trust flow.
3. Execute bidirectional stdin/stdout transfers (including random bytes, NUL, large output), PTY/resize, then SFTP and simultaneous sidecars; measure memory/queue ceilings under a deliberately slow peer.
4. Exercise real invalid/expired/revoked Access sessions with G2, no manual Cookie copying. Verify edge 302/403/offline behavior without assuming local mocks exactly represent every tenant.
5. Validate real mobile/Wi-Fi transitions, suspended/resumed app behavior, and cancellation during each phase. A new connection must not replay old SSH bytes or unconfirmed commands.

No existing unrelated Cloudflare hostname should be used as a speculative SSH test target. The local implementation permits further work while these compatibility and authentication gates remain explicit.
